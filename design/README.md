# Дизайн (Storybook)

Кодовые макеты дизайна платформы турниров ФНТ РК. Картинку-ориентир рисует
ChatGPT (`gen/`), а настоящий компонент собираем здесь кодом. Стек: **React 18 +
Storybook 8 (Vite)**, тёмная glass-тема (`gen/frame.css`), токены (`src/tokens.css`),
иконки `lucide-react`.

## Главное правило: в Storybook показываем ТОЛЬКО флоу

В историях Storybook выносим **только флоу-борды** (путь пользователя —
последовательность экранов со стрелками-переходами). **Отдельные экраны как
самостоятельные истории не показываем.** Так понятнее и организованнее: видно
весь сценарий целиком, а не разрозненные куски, и в списке Storybook — коротко.

- **Флоу** = одна история (`parameters: { layout: 'fullscreen' }`); внутри —
  экраны-колонки + стрелки. Примеры: `PlayerFlowBoard`, `TournamentFlowBoard`.
- **Экран** = обычный React-компонент (`TournamentDetail`, `LiveMatch`, …). Он
  **не** заводится отдельной историей — только используется внутри флоу.
- Новый экран → добавляем его в нужный **флоу-борд**, а не в отдельную историю.
- Один `*.stories.tsx` = один флоу (одна история `Флоу`).

## Структура: платформа → роль (глобальное — в «Обзор»)

Верхний уровень дерева — **платформа**, дальше — **роль**. Сквозные вещи, которые
относятся ко всему сразу, — в разделе **Обзор** (не под конкретную роль).

- **Обзор** — глобальное: `Карта флоу` (полный ход турнира из D2).
- **Веб** —
  - `Судья стола` — ведение матча;
  - `Судья` — заявка на судейство, организация турнира;
  - `Главный судья` — `Обзор` (дашборд), `Сетка` (посев/жеребьёвка), `Игроки`
    (участники), `Столы` (распределение);
  - `Федерация` — `Календарь и приёмка`, `Взносы`, `Игроки и рейтинг`, `Судьи`,
    `Турнир` (карточка).
- **Мобильное приложение** — `Игрок` (приложение, турнир, новости, заявка на турнир).

## Веб-флоу — четыре версии: десктоп, таблет (портрет + альбом), мобилка

Веб **адаптивный**, поэтому **каждый флоу веба существует в четырёх раскладках —
десктоп, планшет-портрет, планшет-альбом и мобилка**: один и тот же сценарий, разная
вёрстка под экран. В Storybook это истории под ролью: `Десктоп`, `Таблет`,
`Таблет · альбом`, `Мобилка`. Роли-судьи и федерация начинаются с десктопа, но
обязаны работать и с планшета/телефона.

- **Планшет-альбом** — планшет держат чаще горизонтально; веб на нём ≈ компактный
  десктоп. Реализовано так: тот же десктоп-layout (шапка + сайдбар + main) в
  горизонтальной рамке ~1024×720 через `Desk variant="land"` (см. `deskShell.tsx`,
  класс `.deskland` в `gen/desktop.css`). Борд рисуем с `frame="land"`.
- **Планшет-портрет** — узкая раскладка (стек / две колонки), рамка `Tab` из
  `respShell.tsx`.

**Мобильное приложение** (нативное, игрок) — только телефон, версий под ширину не нужно.

## Сетка — настоящий компонент, не мокап

Экран «Сетка» рендерит **реальный `BracketFlow`** (React Flow, `@xyflow/react`) из
`front/`, подключённый алиасом `@` (см. `.storybook/main.ts`, там же dedupe React,
т.к. design на 18, front на 19). Сетка — на весь экран, как карта (пан/зум), с
большим посевом (128 участников), чтобы был виден масштаб реального турнира.

## Примерка шрифтов

Гарнитура переключается **в тулбаре сверху** (пункт «Шрифт», значок ¶) — прямо на
любом экране, без перезагрузки. Работает так: декоратор в `.storybook/preview.tsx`
подменяет токен `--font` на `:root`, а на этом токене сидит вся вёрстка макетов
(`gen/frame.css`, `gen/desktop.css`, `tokens.css`, `body` в `tokens.css`).

- Список гарнитур — `src/fonts.ts`, он же единственный источник: ссылка на Google
  Fonts собирается из него. Добавить новую = добавить строчку в `FONTS`.
- В списке только шрифты с кириллицей **и казахскими буквами** (ә ғ қ ң ө ұ ү һ і) —
  проверено по `unicode-range` у Google. Поэтому там нет Anton, Archivo Black,
  Barlow/Saira Condensed (нет кириллицы вовсе) и Russo One, Jost, Stalinist One
  (кириллица есть, казахских букв нет).
- Группа **«Под знак ФНТ»** — узкие тяжёлые гротески, родня надписи `TTFRK` на
  логотипе (`brand/fnt/`). В специмене такие карточки идут со знаком рядом, чтобы
  сразу видеть, дружит гарнитура с логотипом или спорит.
- Сравнить все сразу — история **Дизайн-система → Шрифты → Специмен**: один и тот
  же кусок интерфейса турнира (заголовок, счёт, таблица рейтинга, кнопка) каждым
  шрифтом.
- Прибить конкретный шрифт к истории: `globals: { font: 'onest' }` в её аннотации.
- Ссылка на экран с нужным шрифтом: `?globals=font:golos` в URL.
- Шрифты грузятся с Google Fonts — без интернета остаётся системный.

## Публикация: деплой на каждый пуш

Storybook живёт на **https://storybook-static-nu-two.vercel.app** и собирается
Vercel'ом сам — руками ничего заливать не надо.

- Проект Vercel `storybook-static` подключён к репозиторию
  `AssylanAkhanuly/tt_tournament`, продакшн-ветка — `main`. Пуш в `main` →
  прод-деплой; пуш в другую ветку / PR → превью-деплой со своей ссылкой.
- Корень проекта — папка `design/`, сборка и вывод описаны в `design/vercel.json`
  (`npm install` → `npm run build` → отдаём `storybook-static/`).
- «Ignored Build Step» на Vercel: `git diff --quiet HEAD^ HEAD -- . ../front/src`.
  Сборка запускается, если коммит изменил `design/` **или** `front/src` — второе
  обязательно, потому что экран «Сетка» тянет настоящий `BracketFlow` из
  `front/` по алиасу `@`. Правки только в `TZ.md`/диаграммах деплой не гоняют
  (такой деплой Vercel показывает как `CANCELED` — это норма).
- В настройках включён доступ к файлам вне корня проекта
  (`sourceFilesOutsideRootDirectory`) — без него `../front/src` не виден сборке.
- **Автор коммита обязан быть `assylan.akhanuly@gmail.com`.** Vercel сверяет
  e-mail автора с аккаунтом, у которого есть доступ к проекту; коммиты от
  чужого адреса (например `…@users.noreply.github.com` из бот-окружения) дают
  деплой в статусе `BLOCKED` — сборка даже не стартует. Это же правило
  действует для проекта `tt-tournament` (фронт).
- Ручной деплой (если очень нужно): `cd design && npx vercel deploy --prod`.
