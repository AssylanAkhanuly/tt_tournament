# Тестирование системы

Система — три стека (Django-бэкенд, Next.js-веб, Expo-приложение), поэтому «одна
библиотека» не покрывает всё: инструмент на каждый слой свой. Ниже — что чем
тестируем и **что разрабатываем по TDD**.

Сейчас тестов в коде **нет ни в одном модуле** (`back/`, `front/`, `mobile/`), а
логика уже есть — в первую очередь движок сеток `back/tournaments/bracket.py`.
Его и рейтинг покрываем в первую очередь.

## Что разрабатываем по TDD

TDD (сначала тест, потом код) применяем там, где логика **чистая и цена ошибки
высокая** — тесты пишутся раньше кода и служат спецификацией:

1. **Движок турниров** — `back/tournaments/bracket.py`: генерация сетки по
   форматам, посев, bye при нечёте, продвижение победителя, маршрут в консолацию/
   нижнюю сетку, автоназначение стола, определение мест. Табличные тесты по
   [ENGINE.md](ENGINE.md) и [TZ.md](TZ.md) §5: перебор числа участников, посев vs
   жеребьёвка, walkover.
2. **Рейтинг судей S1–S4** — прямо из таблиц [TZ.md](TZ.md) §7.2: сами таблицы
   баллов и есть тест-кейсы (статус × роль × коэффициент 1,5, неявка −1, зачёт
   ≥3 из 4, тай-брейки S1→S2→S3→S4). Идеальный случай для TDD.
3. **Рейтинг игроков** — как только определят методику (QUESTIONS **5.1**).
4. **Расчёт расписания** (подсказка §5.3): сколько матчей, времени, влезает ли.
5. **Инварианты и права** — стол не занят дважды, победитель не продвигается
   дважды, рейтинг не задваивается, `_can_manage_tournament` / `_can_create`.

**Не по строгому TDD** (тест-после / исследовательская разработка): экраны,
вёрстка, навигация. Но их **логику** (жадное бесконфликтное расписание очереди
матчей, раскладка сетки) выносим в юниты и покрываем.

## Библиотеки по стекам

| Слой | Библиотека | Почему |
|---|---|---|
| **Бэкенд** (Django/DRF) | **pytest** + **pytest-django** | `parametrize` идеален для перебора форматов/участников движка и таблиц рейтинга; меньше boilerplate, чем у `unittest` |
| — фикстуры данных | **factory_boy** | турниры, участники, матчи без ручного заполнения |
| — API/права | DRF **APIClient** (встроен) | эндпоинты, коды, права ролей |
| **Веб** (Next.js/React) | **Vitest** + **React Testing Library** (+ jest-dom, user-event) | Vitest — тот же Vite-тулчейн, что у Storybook; быстрый, ESM/TS из коробки |
| — E2E | **Playwright** | живое табло, несколько вкладок (судья + зритель), SSE-поток, кросс-браузер; надёжнее Cypress на мультивкладке |
| **Приложение** (Expo/RN) | **Jest** + preset **jest-expo** + **@testing-library/react-native** | стандарт Expo; работает с RN 0.86 / React 19 |
| — E2E | **Maestro** | YAML-флоу, дружит с Expo; проще Detox в поддержке |
| **Нагрузка** | **k6** | этап 5 требует нагрузочное тестирование; держит много соединений — проверяем в т.ч. потолок одновременных SSE — наш технический предел, меряем нагрузочным тестом. Альтернатива на Python — Locust |
| **Storybook** (по желанию) | play-функции / Storybook test-runner | интеракционные тесты компонентов, если нужно |

Единый стиль: юнит + интеграция на каждом слое; E2E — на критичных сквозных
сценариях (провести турнир, свести счёт, увидеть на табло), не на всём подряд.

## Особые места этой системы

- **Реальное время** (SSE, LISTEN/NOTIFY): интеграционный тест — запись очка
  делает NOTIFY, слушатель получает событие; E2E — счёт появляется на второй
  вкладке-табло.
- **Офлайн-очередь судьи**: тест синхронизации и разрешения расхождений
  (приоритет у судьи стола), порядок по `at_device`.
- **Идемпотентность**: повторный результат не двигает сетку и не задваивает
  рейтинг.

## Запуск

```bash
# бэкенд (venv Django)
back/venv/Scripts/python.exe -m pytest            # после установки pytest+pytest-django

# веб
cd front && npx vitest            # юниты; npx playwright test — E2E

# приложение
cd mobile && npm test             # jest-expo

# нагрузка
k6 run load/scoreboard.js         # потолок SSE-соединений и т.п.
```

## CI

Прогон в GitHub Actions на пуш/PR: `pytest` (back) + `vitest` (front) + `jest`
(mobile), затем E2E (Playwright/Maestro) на ключевых сценариях. Падение любого —
красный билд. Нагрузочные — отдельным ручным/ночным прогоном, не на каждый пуш.
