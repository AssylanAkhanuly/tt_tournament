# Фронт (веб) — Claude Context

Правила этого модуля. Про проект целиком — корневой `CLAUDE.md`: источники
правды, синхронизация документов, диаграммы, коммиты. Здесь только то, что
касается веба.

Часть рабочих правил ниже перенесена из образца `docs/refs/claude-md-bevr-obrazec.md`
(другой продукт, другой стек) — взято то, что про **как работать**, а не про его
библиотеки. Где наши обстоятельства другие, правило переписано под них, а не
скопировано.

## Стек

- **Next.js 16** (App Router), **React 19**, **TypeScript**.
- **Структура — Feature-Sliced Design**: `src/{shared,entities,features,widgets,views}`,
  импорт только «вниз» (`views → widgets → features → entities → shared`).
  `app/` — только Next-роутинг (тонкие `page.tsx`/`layout.tsx`), зовёт `views`.
  Алиас `@/* → src/*` (плюс fallback `./*` для `app/`).
- **Набор компонентов — `src/shared/kit/`** ✳ (01.09.2026): оболочки ролей,
  доменные компоненты, календарь, графики, токены и темы. Storybook в `design/`
  импортирует его отсюда по тому же алиасу `@`. Раньше кит жил в `design/`, и
  перенос экрана означал переписывание.
- **Тема светлая, одна** ✳ (01.09.2026): `--bg`, `--card`, `--text` и соседние
  в `app/globals.css` держат светлые значения, `color-scheme: light`. Тёмной
  темы у приложения нет. Единственное тёмное место — **плашка табло**: у неё
  своя вещательная палитра `--sb-*`, её смотрят в эфире поверх видео.
- **Мультиязычность — i18next + react-i18next** (RU/KK/EN). Ресурсы —
  `src/shared/i18n/locales/{ru,kk,en}/*.json`.
- **API** — проксируется через `next.config.ts` (`/api/*` → Django), JWT в
  httpOnly-куках первой стороны.

## Команды

```bash
npm run dev            # Next dev
npm run build          # прод-сборка
npm run kit:css        # пересобрать Tailwind кита (src/shared/kit/tailwind.css)
npm test               # Vitest
npm run test:e2e       # Playwright
npx tsc --noEmit       # типы
```

`npm run kit:css` обязателен после правки классов в ките: собранный CSS лежит в
репозитории, и без пересборки новые классы просто не появятся. Тот же скрипт
зовёт `design` через `npm --prefix ../front`.

## Стили: где Tailwind, где CSS Modules, где нативный CSS

Правило одно и оно про **происхождение** разметки, а не про вкус.

| Что | Чем |
|---|---|
| **Кит** (`src/shared/kit`) и всё новое, что из него собрано | **Tailwind + HeroUI** |
| **Экраны, написанные до кита** (`views`, `widgets`) | **CSS Modules** — не переписываем ради переписывания |
| **Плашка табло** (`widgets/scoreboard`) | своя вещательная палитра и CSS Modules: её смотрят в эфире поверх видео, она не обязана совпадать с интерфейсом |
| То, чего Tailwind не выражает | нативный CSS: `@keyframes`, `clip-path`, псевдоэлементы, `::-webkit-*`, `color-mix()` от токенов, печать |

**Tailwind подключён с выключенным preflight.** Его сброс снёс бы вёрстку
файлов, написанных до него; вместо этого в `tailwind.src.css` лежит локальный
сброс внутри `.hero-scope`. Не включать preflight «чтобы было правильнее» —
сломается всё сразу и незаметно.

### Практики, по убыванию пользы

1. **Каждое значение цвета и радиуса — токен.** Сырых `#3987e5` и
   `border-radius: 12px` в коде быть не должно: они невидимы для смены темы.
   Источник — `src/shared/kit/theme/tokens.css`. Проверяет
   `cd design && npm run lint:colors`, он сканирует и кит, и макеты.
2. **Углы прямые.** `--r-*` = 0: это рабочая система федерации, а не
   потребительское приложение. Круглым остаётся круглое по сути — точки
   состояний, фото людей, тумблер.
3. **Сначала компонент кита, потом свой.** Прежде чем стилизовать `<button>`,
   посмотрите, нет ли этого в `shared/kit/app`. Второй набор кнопок — это
   дизайн-система, разошедшаяся надвое.
4. **Никаких `style={{}}` для статики.** Инлайн-стиль сильнее любого класса, и
   вызывающий уже ничего не поправит. Он законен для вычисленного: ширина
   колонки грида, процент от состояния, координата.
5. **Не `!important`.** Если класс не побеждает — виноват инлайн-стиль или
   дубль в строке классов; у обоих есть починка выше.
6. **Специфичность считают, а не подбирают.** У `[data-on][data-on]` в ките
   селектор удвоен намеренно: он обязан быть тяжелее полосы `:nth-child(even)`,
   и это записано в комментарии. Молчаливое «добавил класс, вроде заработало»
   ломается на следующей сборке.
7. **Прокручиваемая колонка-flex не даёт детям ужиматься.** ✳ (04.09.2026)
   Рабочая область оболочек (`kit/app/chrome.tsx`) — `flex flex-col
   overflow-auto`, а `flex-shrink` по умолчанию равен единице. У блока с
   `overflow-hidden` (панель, карточка, обёртка с рамкой) минимальная высота по
   содержимому не считается — по правилу флексбокса `min-height: auto` у такого
   элемента равна нулю. Значит длинный экран не уезжает в прокрутку, а
   размазывается: каждая панель ужимается и режет своё содержимое. Замер до
   правки — 204 обрезанных панели на 16 ролях из 18. Лечится на контейнере
   (`[&>*]:shrink-0`), а не на панели: следующий блок получит правило сам.
   Проверяется скриптом в браузере — панель обрезана, если у неё
   `scrollHeight > clientHeight`.

## Проверка — что значит «готово»

**Не докладывать о работе как о сделанной, пока не запустил и не прочитал
вывод.** Зелёная сборка — не доказательство, что фича работает.

Отчитываться **раздельно**: типы, юниты, e2e, ручная проверка. И отличать
новые падения от тех, что были до вас.

Что известно про этот модуль:

- `npx tsc --noEmit` даёт **одну давнюю ошибку** в `BracketFlow.tsx` (`.at()`),
  она не ваша — упоминайте её отдельно.
- `e2e/scoreboard.spec.ts` **не запускается без Django на :8000**: пульт пишет
  состояние через прокси, и без бэкенда набор падает на первом же тесте. Это не
  повод объявить его пройденным.

### Изменил вид — посмотри на вид

Любая правка, которая что-то рисует, проверяется **скриншотом, который вы
открыли и прочитали**. Не «сделал снимок», а посмотрел: текст читается, у
кнопок есть подписи и настоящие размеры, ничего не схлопнулось, не наехало и не
исчезло.

Для этого модуля это особенно важно в двух местах:

- **Плашка табло идёт в эфир поверх видео.** Ошибка контраста видна только на
  картинке — в разметке она выглядит нормально.
- **Кит светлый, а пульт табло тёмный.** Компонент, который в Storybook
  выглядел правильно, внутри тёмного экрана может потерять текст.

### Проверка должна уметь упасть

Каждое утверждение теста обязано быть таким, чтобы **сломанная реализация его
завалила**. Прежде чем писать — спросите: от какой правки это покраснеет? Если
почти ни от какой, оно бесполезно. Запрещено, потому что проходит на пустой
странице:

```ts
expect(hasFallback || hasContent).toBe(true);   // ✗ проходит на чём угодно
expect(response.status()).toBe(200);            // ✗ ответил ≠ ответил верно
await expect(page.locator('body')).not.toContainText('Error'); // ✗ «не упало»
```

Проверять надо настоящее: конкретный счёт в конкретной ячейке, что подача
перешла к другому игроку, что после «Завершить партию» счёт партий вырос.

### Проверяй там, где оно работает

Зелёный `localhost` не значит, что работает на Vercel: там другой режим сборки,
другие переменные и живой Django. У проекта **два деплоя** из одного
репозитория — `tt-tournament` (это приложение) и `storybook-static` (`design/`).
Правка в ките задевает оба.

### Честность

- Отличайте «типы сходятся» от «я проверил, что фича работает». Говорите, что
  именно сделали.
- Если что-то не проверено, заблокировано или проверено частично — так и
  скажите, не округляйте до успеха.
- Проверка, написанная под сломанное поведение, — это сообщение о баге, а не
  зелёный тест.

## SOLID применительно к этому коду

Общая формулировка — корневой `CLAUDE.md` → «Как пишем код». Здесь то же
самое на слоях этого модуля.

- **Одна ответственность** — `entities/*` владеет транспортом и моделью,
  `widgets/*` — композицией, `app/*/page.tsx` — только маршрутом. Не ходить
  `fetch`-ем из компонента. Файл, начавший делать две работы, разделить до
  того, как он возьмётся за третью.
- **Открыт для расширения** — добавлять, а не править существующее. Новый режим
  табло не должен означать правку всех остальных.
- **Подстановка** — то, что стоит за общим контрактом, должно быть заменяемо, в
  том числе на предрендеренных страницах.
- **Разделение интерфейсов** — компонент принимает те пропы, которыми
  пользуется, а не объект-бог. `player`, `onPoint` лучше, чем весь стейт доски.
- **Инверсия зависимостей** — зависеть от абстракции нижнего слоя. Экран зовёт
  `useScoreboardChannel`, а не `fetch` напрямую.

## Табло трансляции (`/scoreboard`)

Оверлей счёта для OBS + пульт оператора. Разряд встречи (одиночный · парный ·
командный) выбирают таббаром сверху пульта, он же решает, что идёт в эфир:
второе имя стороны или счёт команд над игроками. Состояние **не на фронте**: оно
живёт в Django (`back/scoreboard`, строка на стол). Пульт пишет `PUT` с версией
`rev`, обе стороны читают через одно соединение SSE (`…/stream/`) — опроса у
клиента нет. Транспорт заперт в
`src/features/scoreboard-live/useScoreboardChannel.ts`, там же запасной путь на
опрос, если поток где-то буферизуется. Подробности, цена в потоках gunicorn и
настройка источника в OBS — в `README.md`.

**Плашка — вещательная графика, а не интерфейс.** У неё своя палитра
(`--sb-*` в `app/globals.css`), и она намеренно не совпадает с китом: её
смотрят поверх видео. Правила внутри неё: счёт встречи всегда с хозяином —
число стоит вплотную к своему названию команды (а не парой «2 : 1» посреди
полосы), **ведущая команда залита акцентом**, при равенстве не выделен никто;
без названий команд остаётся подпись «счёт встречи». Очки громче партий.

## Конвенции

- Один компонент — своя папка в нужном слое FSD; стили рядом (`*.module.css`)
  либо классами кита, по правилу выше.
- Общие примитивы — `src/shared/ui` и `src/shared/kit`; бизнес-сущности —
  `src/entities`; пользовательские действия — `src/features`; составные блоки —
  `src/widgets`; композиции страниц — `src/views`.
- `aria-label` и `data-testid` — часть контракта: на них держатся e2e.
  Переименовали — почините спеки в том же изменении, а не «потом».
