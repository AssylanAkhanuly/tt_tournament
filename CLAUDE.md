# CLAUDE.md — как мы ведём этот проект

Цифровая платформа турниров для Федерации настольного тенниса РК (ФНТ РК).
Этот репозиторий держит и спеку/диаграммы, и код. Код — в подпапках `front/`
(Next.js 16 + React 19, стили — Tailwind + HeroUI, нативный CSS там, где Tailwind
не тянет), `back/` (Django 5 + DRF), `mobile/` (Expo 57
+ RN 0.86); у каждой **свой `CLAUDE.md`** с деталями модуля — читать его перед
работой в этом модуле. В корне — спека, диаграммы, дизайн-макеты.

Язык проекта — **русский**: документы, диаграммы, комментарии, коммиты.

## ГЛАВНОЕ ПРАВИЛО: новые данные — сразу во все нужные файлы

Когда приходит новое решение/факт/документ — не правим один файл, а **сразу
синхронизируем все, где это отражается**, и перерисовываем схемы. Иначе файлы
разъезжаются.

| Что пришло | Куда сразу вносим |
|---|---|
| **Новое правило / требование** | `TZ.md` + соответствующий `diagrams/flow-*.d2` + `ARCHITECTURE.md` (если архитектурное) + перерисовать |
| **Новая/изменённая сущность или поле данных** | `diagrams/domain.d2` (**источник**) → `python diagrams/sync-domain.py` → перерисовать `architecture.d2`; **и** ER-схема в `ARCHITECTURE.md` (mermaid) — руками, это вторая копия |
| **Решение федерации по открытому вопросу** | `QUESTIONS.md` (убрать из блокеров, записать решение) + пробросить в `TZ.md` и схемы |
| **Присланный документ (PDF и т.п.)** | копия в `docs/refs/` + оцифровать значения в `TZ.md` (таблицы/числа, а не отсылку) |
| **Правило работы самого движка/рейтинга** | `ENGINE.md` / `TZ.md` §7 + `flow-engine.d2` / `flow-judge-rating.d2` |

Если заметили рассинхрон, который не входит в текущую задачу — **флагаем его
пользователю**, а не тихо переписываем. (Известный дрейф ER: сущности и поля
турнира сведены с `domain.d2` 12.08.2026; открытым остался `BRACKET_TEMPLATE` —
он есть только в `ARCHITECTURE.md`, решение по нему не принято.)

## Диаграммы (D2)

- Бинарь: `C:/Program Files/D2/d2.exe`.
- **Собрать всё:** `powershell -ExecutionPolicy Bypass -File diagrams/build.ps1`.
  Скрипт сам запускает `sync-domain.py` и рендерит каждую `*.d2` → SVG + PNG.
  `.ps1` держать **только в ASCII** (Windows PS 5.1 иначе ломает кириллицу).
- **Раскладка (важно):** `flow-*` и `domain` — через **dagre** (сохраняет
  направление при циклах-петлях и не растягивает ER); всё остальное
  (`architecture` и т.п.) — через **elk**.
- **Доменная модель — один источник:** правим `diagrams/domain.d2`; в
  `architecture.d2` она вклеивается скриптом `sync-domain.py` в метку
  `# DOMAIN-MODEL-HERE`. Встроенную копию руками **не трогаем**.
- **Hi-res PNG** (для чтения): Chrome headless
  `C:/Program Files/Google/Chrome/Application/chrome.exe`
  `--headless=new --force-device-scale-factor=N --window-size=W,H --screenshot`.
  Пределы Chrome: высота ~**15000 px**, ширина ~**16384 px** — за ними картинка
  выходит пустой/обрезанной (признак — подозрительно маленький файл). Широкие
  схемы рендерим на 1x, не задирая scale.
- После правки `.d2` — **перерисовать и глазами проверить** результат (`Read`
  по PNG), а не полагаться на то, что «скомпилировалось».

## Дизайн-пайплайн (`design/`)

Разделение труда: **ChatGPT рисует картинку-ориентир → Claude собирает по ней
настоящий компонент Storybook** (чёткий текст, реальные токены).

- **Экран сначала проектируется вариантами** (с 22.08.2026). Не «нарисовал и
  положил в борд», а: 2–4 варианта одного экрана рядом, у каждого разбор
  «за что / чем платим / сверх флоу» → федерация выбирает → решение пишем в
  `flows/*.md` строкой «дизайн: вариант Б, дата» → выбранный вариант заменяет
  макет в `design/src/mockups/roleNN.tsx` → `npm run gen:flows`. Варианты живут
  в `design/src/design/` и показываются разделом **Дизайн** в Storybook.
  Содержание у вариантов одно и то же и берётся из `flows/*.md`; отличается
  решение. Порядок ролей начат со **спортсмена** (роль 14). Подробности —
  `design/README.md`, раздел «Порядок работы».
- **Вариант рисуется до конца.** Три раскладки из одинаковых плоских
  прямоугольников — не три варианта дизайна, а один вайрфрейм в трёх позах:
  выбирать по ним нечего. Нужны контрастная типографическая шкала (дисплейная
  гарнитура `--font-brand` на числах и фамилиях), слои вместо однотонных
  заливок, доменные вещи нарисованные по-своему (счёт по партиям как на табло,
  форма игрока, личные встречи), настоящий Chart.js вместо самодельной ломаной
  и изображения там, где они в системе есть. Таблица признаков —
  `design/README.md`.
- **Варианты рисуем на светлой теме** (решение от 22.08.2026): в историях
  раздела «Дизайн» прибито `globals: { theme: 'daylight-fnt' }` — светлая на
  синем знака ФНТ. Тёмная остаётся в тулбаре и в остальных разделах. Текст
  поверх фотографий — только `--c-on-media` / `--c-on-media-2`: шторка тёмная
  при любой теме, а `--c-ink` на светлой почти чёрный и пропадает.

- `design/gen/design.mjs` — генератор картинок (`gpt-image-1`) из брифа
  `design/gen/briefs/*.md` + арт-дирекшн `context.md`. Запуск из `design/`:
  `node --env-file=../.env gen/design.mjs <бриф>`.
- Картинка — **только ориентир** (модель искажает текст). Финал — код в
  `design/src/*.tsx` (+ `.stories.tsx`). Storybook: `npm run storybook`.
- **Стек стилей: Tailwind — основной** ✳ (30.08.2026). Решение принято вместе с
  подключением библиотеки **HeroUI** (`@heroui/react`), которая на Tailwind и
  построена. Граница простая:

  | Чем | Что им делаем |
  |---|---|
  | **Tailwind** | всё, что он умеет: раскладка, отступы, типографика, состояния, адаптив |
  | **Нативный CSS** | то, чего Tailwind не умеет или умеет плохо: `clip-path` и сложные формы, `@keyframes` и анимации, псевдоэлементы с рисованием, `color-mix()` от токенов, печать, тонкая работа с `::-webkit-*` |

  Нативный CSS не «наследие», а вторая половина стека: у кита, например,
  трапециевидный язычок и пульсация кольца сделаны им, потому что Tailwind
  такие вещи не выражает.

  Tailwind подключён **с выключенным preflight**: его сброс стилей снёс бы
  вёрстку двухсот файлов, написанных до него. Приложение (`mobile/`) остаётся
  на **штатном `StyleSheet` из React Native** — Unistyles не подключён, не
  импортируем его, пока библиотеку не завели осознанно.
- **Цвет и форма — только токенами.** Единственный источник —
  `design/src/theme/tokens.css`; «сырых» `#hex`/`rgba()` и `border-radius: 12px`
  в макетах, примитивах и инлайн-стилях быть не должно, полупрозрачные варианты
  считаются через `color-mix()` от токена. Темы — `design/src/theme/themes.ts`,
  примитивы — `design/src/ui`. Перед «готово»:
  `cd design && npm run lint:colors` (ловит сырые цвета, сырые радиусы и ссылки
  на переименованные токены). Подробности — `design/README.md`.
- **Углы интерфейса прямые** (`--r-*` = 0): это рабочая система федерации, а не
  потребительское приложение. Круглым остаётся только круглое по сути — точки
  состояний, фото людей, тумблер, «остров» камеры — и корпуса устройств в
  макетах (`--r-device-*`).

## Чтение PDF

## Честность и проверка

- Если чего-то нет в первоисточнике — **так и говорим** (не выдаём вывод за факт
  документа). Спорные места помечаем как открытый вопрос.
- Перед «готово» — перерисовать/пересобрать и проверить результат по факту.

### E2E-проверка каждой фичи обязательна (не считаем фичу готовой без неё)

- **Веб (`front/`):** любую разработанную фичу проверяем сквозным **Playwright
  e2e** — в реальном браузере, по пользовательскому сценарию (клики, ввод,
  переходы, видимость элементов), не только `tsc`/юнит.
- **Мобилка (`mobile/`, RN):** любую фичу проверяем **на Android-эмуляторе
  e2e** — поднимаем dev-build, гоняем сценарий вживую (запуск, экран, жесты),
  снимаем скриншот. Skia/жесты в Expo Go не работают — нужен dev-build.
- Детали подхода и библиотек — в `TESTING.md`.
